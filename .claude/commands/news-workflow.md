뉴스 수집기 앱의 새 기능 개발 워크플로를 아래 순서대로 실행해 줘. 각 단계가 끝나기 전에는 다음 단계로 넘어가지 마.

## 1. 현재 상태 확인

- `git status`와 `git branch --show-current`로 현재 브랜치와 작업 트리 상태를 확인한다.
- main 브랜치가 아니면 경고하고, main으로 이동할지 사용자에게 물어본다. 사용자가 승인하기 전에는 이동하지 않는다.
- 커밋되지 않은 변경이 있으면 알려 주고, 어떻게 할지 물어본다.

## 2. 브랜치 생성

- 브랜치 이름: `$ARGUMENTS`
- 이름이 비어 있으면 어떤 기능을 개발할 것인지 물어보고, **영어 소문자-하이픈 형식**(예: `category-filter`)으로 이름을 제안한다. 사용자가 확인하면 그 이름을 쓴다.
- 이미 같은 이름의 브랜치가 있으면 알려 주고 다른 이름을 제안한다.
- `git switch -c <브랜치 이름>`으로 생성하고 이동한다.

## 3. 개발 시작 안내

- 브랜치 생성이 끝나면 **"이제 개발을 시작하세요!"** 라고 안내한다.
- `CLAUDE.md`를 다시 읽고 이 프로젝트의 기술 스택과 컨벤션을 요약해서 알려 준다 (스택, 범위, 아키텍처 규칙, 인증·보안, UI 가이드 `ui.md` 등).
- 이후 사용자가 요청하는 개발 작업을 평소처럼 수행한다.

## 4. 완료 처리

사용자가 **'완료'** 또는 **'done'** 이라고 입력하면:

1. `git status`와 `git diff --stat`으로 변경된 파일 목록을 보여준다.
2. 변경 내용을 바탕으로 커밋 메시지를 자동으로 제안한다. 이 저장소의 기존 커밋 스타일(`git log`)을 따른다 (한국어, 한 줄 요약).
3. 사용자가 확인하면 변경 파일을 stage하고 커밋한다. 수정을 원하면 메시지를 고쳐서 다시 확인받는다.
4. 커밋 후 main으로 이동해 개발 브랜치를 병합한다 (`git switch main` → `git merge <브랜치 이름>`). 충돌이 나면 중단하고 사용자에게 알린다.
5. push와 브랜치 삭제는 사용자가 요청하기 전에는 하지 않는다.

## 5. 작업 요약

병합이 끝나면 다음을 요약해서 보여준다:

- 브랜치 이름과 병합 결과
- 커밋 메시지와 변경된 파일 목록
- 구현한 기능의 핵심 내용
- 남은 작업이나 확인할 점 (있다면)
